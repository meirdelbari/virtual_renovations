AlgoreitAI (Nano Banana) Integration Log
=======================================
Date: November 29, 2025

NOTE (2026): This file is a historical log and may reference older paths (e.g. `backend/...`).
Current implementation lives under `api/` and local secrets go in the repo root `.env`.
See `QUICKSTART.md` and `Docs/PROJECT_STRUCTURE.md` for the up-to-date setup.

Summary
-------
Successfully integrated AlgoreitAI, built on Google's "Nano Banana" (Gemini 2.5 Flash Image) model, for AI-powered room renovations. The application now supports sending room photos with natural language instructions to Google's state-of-the-art image generation model.

Update: December 27, 2025 - Supplier Product Integration & Logic Refinement
---------------------------------------------------------------------------
Significant updates to support precise Supplier Product integration and streamline user flows.

1. **Supplier Product "Insert" Logic**:
   - **Collage Generation**: When a supplier product is selected, the frontend builds a side-by-side collage (Room | Product) instead of overlaying or just sending the room.
   - **Prompt Engineering**: The prompt was overhauled for supplier products. It now explicitly instructs Gemini to:
     - Treat the input as a collage.
     - "INSERT" the product from the right panel into the room on the left.
     - **PRESERVE** existing furniture and room details (preventing unwanted re-staging).
     - Output only the modified room (left side).
   - **Post-Processing**: The client automatically crops the result to remove the reference panel if a collage was used.

2. **Flow & Selection Logic Updates**:
   - **Style Bypass**: Selecting a Supplier Product now bypasses the mandatory "Style" selection step. The product itself acts as the style reference.
   - **Furniture Remove**: The "Remove" action also bypasses the Style requirement.
   - **Renovate -> Supplier**: This flow now opens the Product Selector directly, allowing users to filter by style inside the modal rather than being blocked.

3. **User Experience**:
   - **Working Area Preview**: The Working Area now updates immediately to show the side-by-side collage when a product is selected, giving visual confirmation of the input state.
   - **No Pop-ups**: Removed blocking alerts ("Please select a Style") in favor of a smoother, non-blocking flow.

Update: December 27, 2025 (Evening) - Preservation Logic
--------------------------------------------------------
Addressed user feedback that adding a single product was causing the AI to re-stage the entire room (changing sofas, rugs, walls).

1. **Strict Preservation Prompting**: 
   - Changed instructions from "Renovate" to "INSERT".
   - Added specific constraint: "PRESERVE the existing room details... and EXISTING FURNITURE... Only move/remove items if they physically conflict."
   - Explicitly commanded: "Do not re-stage the entire room."

2. **Visual Strategy**:
   - Reverted from "Overlay" back to "Side-by-Side Collage" as the overlay was confusing the AI about what was "real" in the scene. Side-by-side provides a cleaner "Source -> Target" operation for the model.

Update: December 5, 2025 - Furniture Module
-------------------------------------------
Added specialized prompting logic for the new "Furniture" feature to handle contradictory constraints better than the generic renovation prompt.

1. Furniture Removal (`furniture_clear_remove`):
   - Prompt explicitly instructs AI to *ignore* the selected style and purely reveal the original room shell.
   - Focuses on inpainting floors/walls with original materials.

2. Virtual Staging (`furniture_stage_room`):
   - Prompt injects context about the room type (e.g., "as a bedroom") derived from user tags.
   - Focuses on adding furniture that matches the selected style while preserving structural elements.

Technical Implementation
----------------------

1. Backend Integration (backend/geminiClient.js)
   - Created a dedicated client for the AlgoreitAI (Google Gemini) API.
   - Implemented the `processImageWithAlgoreitAI` function.
   - Configured to use the `gemini-2.5-flash-image` model.
   - Authentication via `GOOGLE_GEMINI_API_KEY` environment variable.

2. API Issue Resolution
   - Problem: Initially attempted to use `imagen-3.0-generate-001` endpoint which returned "Model not found" or "Invalid payload".
   - Diagnosis: The search results revealed that "Nano Banana" is the internal/brand name for `gemini-2.5-flash-image`.
   - Solution: 
     1. Switched model ID from `imagen-3.0...` to `gemini-2.5-flash-image`.
     2. Updated the JSON payload structure to match AlgoreitAI's multimodal format:
        ```json
        {
          "contents": [{
            "parts": [
              { "text": "instructions..." },
              { "inline_data": { "mime_type": "image/png", "data": "base64..." } }
            ]
          }]
        }
        ```
     3. Verified successful response handling for `inlineData` image content.

3. Frontend Integration (features/geminiAI.js)
   - Added "✨ AlgoreitAI" button to the UI.
   - Implemented a modal dialog for collecting user instructions.
   - Added auto-prompt generation based on existing Style/Renovation selectors.
   - Handles image conversion to base64 and automatic download of results.

4. Configuration
   - Backend port: 4000
   - Health check endpoint: `/health` (verifies AlgoreitAI configuration).
   - Environment: Requires `GOOGLE_GEMINI_API_KEY` in `backend/.env`.

Endpoints Added
--------------
- POST /api/gemini/process-photo: Main endpoint for image transformation.
- POST /api/gemini/analyze-photo: Endpoint for vision analysis (optional usage).
